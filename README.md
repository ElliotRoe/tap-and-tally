# Tap & Tally

**[tapandtally.com](https://tapandtally.com)**

Wrangle your class's participation. A teacher taps a student, taps what they did, and
Tap & Tally keeps the count. No account, and nothing leaves the laptop.

## What it does

- **Setup in a couple of minutes.** Name a class and paste the roster. Pick Grid or Room;
  for a room, start from a shape (groups, rows, pairs or a U), lay it out full screen and
  seat everyone. Then practise on your real class, and keep or customise what you track.
- **Live Mode.** Start class fills the screen. A bar along the bottom switches between
  the Grid and a Room, the Grid's order, and which room you're in; each class reopens
  the way you left it, with its own seating in every room.
- **Tap to track.** Tap a student, then a button: count every tap, or on/off for the day.
  A −1 fixes a mistake. Tiles show today's total and look faded until someone is tapped.
- **Hold to mark absent.** The tile fills from the left; when it's full, they're marked.
- **Room Layouts and Menus.** Shared libraries, shown as cards. Draw rooms Google Slides
  style (resize, turn, snap to the grid); export either as a file and import a colleague's.
- **Reports.** One table per class for today, this week, this month or all time, with a
  spreadsheet download.
- **Backup and restore.** Everything lives in the browser, so Settings offers a backup file,
  and the side menu nudges after a week without one.

The words used throughout are defined in [CONTEXT.md](./CONTEXT.md). Why things are the
way they are is in [docs/adr](./docs/adr).

## Where things are

- `/`: the welcome page, which goes straight to your first class once one exists.
- `/setup`: the setup steps, for the first class and every new one after.
- `/class/[id]`: a class's own page; `/live/[id]`: Live Mode for it.
- `/room/new`, `/room/[id]`: making and drawing a room, full screen.
- `/layouts`, `/menus`, `/reports`, `/settings`: the rest of the side menu.

The data rules live in `src/lib/domain` (plain TypeScript, unit tested). Saving lives in
`src/lib/store.svelte.ts`, which keeps everything in `localStorage` under one key. The
desert and the hill in the drawings are generated by `scripts/desert-art.py` and
`scripts/hill-art.py`; edit those rather than the SVGs.

## Development

SvelteKit and Bun, with no server or database.

```sh
bun install
bun run check   # types
bun run test    # unit tests
bun run build
```
